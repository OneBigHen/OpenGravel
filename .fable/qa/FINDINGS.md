# Rider QA sweep of production (opengravel.henning.rodeo), 2026-11-14

Method: real Chromium on the Windows PC, real production router, no mocks. Scripts: `scripts/qa/rider-sweep/` (`run.mjs`, journeys under `journeys/`). Raw screenshots: `.fable/qa/out/qa-out/<journey>/<viewport>-<theme>/`; the ones cited below are copied to `.fable/qa/shots/`.
Viewports: iPhone 390x844, 320x568, desktop 1440x900 (plus one landscape 844x390). Caveat: the sweep ran at about midnight Eastern, so "Auto" appearance was Night whenever the phone had a location, and Day (light) only appeared via the menu toggle or when no location was known. Headless Chromium uses software WebGL, so items marked (render?) need a glance on a real phone.

Severity: P0 broken, P1 bad, P2 ugly, P3 nit. Nothing found was a full P0 (the main path works: search, route, loop, save, import, ride screen). Counts: P0 0, P1 8, P2 13, P3 4.

Things that worked well (so the owner knows the sweep was not only negative): first route A-to-B in 2 s (Doylestown to Jim Thorpe), default loop in 2-10 s, GPX import draws its own line, "Ride to start" 51 mi-away prompt shows correctly on the ride screen, reload mid-plan restores the ride ("Restored your ride" in 3 s), offline shows "No signal" and keeps guiding, 60 s of panning and zooming sent zero route requests (idle replanning is NOT a bug).

## Why no test caught it (P0/P1)
- QA-01, 02, 08: no test runs at 320 px or in landscape, and none with a weather alert active (the alert chip is what squeezes the bar). Existing layout specs run at one phone size with empty/fixture weather.
- QA-03: route tests use `OGV_ROUTE_PLAN_FIXTURE=1` (a canned answer), so a real out-of-area request, its 40 s wait and its error screen never run.
- QA-04: no test asks "is a route outside PA/NJ/NY labelled?"; fixtures are all inside the Norristown box.
- QA-05: day-theme screenshots are not taken with live events on the map; tests check the label element exists, not that its text is readable.
- QA-06: edit tests assert the edit controls appear, never that the route is still visible on the map or the stop count is right.
- QA-07: Explore and planner are tested separately; nobody checks that facts survive the handoff (Explore detail -> Ride this -> plan summary).

## Not bugs (checked and clean)
Idle replanning: 60 s of pan/zoom, 0 route-plan requests. Reload mid-plan: ride restored. Console errors: none logged in the 390 flows. Failed requests: only aborted map tiles while panning.

## Not covered (honest list)
Save then rename/delete a saved ride (saw the saved card; did not exercise rename/delete). Share: opened the sheet only, no link created (writes to shared data are forbidden). Spurs while dragging via-points: one drag test only. Satellite white-line check: not done. Offline mid-ride tested once. Loop ride-time chips (3 h, 6 h) were not reached from the UI; the sweep script's selectors for those chips did not take effect.
