## 3. How to operate (read before touching anything)

**Hosts**
- **docker-dev** (this box, 4 CPU / 8 GB): edits and focused tests only. `vitest --maxWorkers=2`. Never `npm run build`, full vitest or Playwright here. Never `pkill -f next`. One heavy worker at a time (it has OOM-crashed).
- **powerplex** (Windows RTX PC, WSL Ubuntu, 64 GB): Codex/DeepSeek workers, gates, data builds. Reach it with `ssh windows-zac "wsl -d Ubuntu -- bash -s" < script.sh`. Inline `bash -c '…'` breaks in Windows cmd; to write files, send base64 lines. It cannot push to GitHub: bundle commits back (`git bundle create - HEAD ^origin/main`), fetch into docker-dev, push from here. Root VHDX is 64 GB: check `df -h /` before blaming flaky tests (99 % full caused "Target crashed"/ENOSPC on 2026-10-28; old `~/swarm/wt` worktrees were 24 GB). Bulk data lives on `/mnt/wsl/ogv-data`.
- **docker-stable / CT109** (megaplex): production. **megaplex github-ci** gate LXC is the alternative gate host (`/root/Vibe/wt/bin/ogv-remote-verify.sh`).
- **MacBook** (`ssh macbook`, user Zachary, wake with the `macbook-wake` skill): Xcode, iOS builds, the paired iPhone. Free Personal Team signing; LaunchAgent re-signs every 6 h.

**Gates** (powerplex, serialized by `~/ogv-verify/.gates.lock`)
- Full: `~/ogv-verify/pp-gates.sh <branch> <sha> lint typecheck vitest build critical` (≈17 min; summary in `~/ogv-verify/runs/<sha12>/summary.txt`).
- Focused: `~/ogv-verify/pp-spec2.sh <branch> <sha> <spec files…>` (vitest + build + chosen specs).
- Known powerplex flakes: `map-gestures.spec.ts:136` (passes on rerun; rerun with `--repeat-each=2`), `avoid-area:264`, `first-route:179/240`, `places.spec.ts:77` (#67). Never accept a flake without a rerun.

**Deploy**: `ssh docker-stable "cd /root/Vibe/wt/og-public && git fetch -q && bash infra/deploy/release.sh origin/main"` (builds an immutable release dir, smoke-tests a candidate on :3299, switches, auto-rolls back). Rollback: `infra/deploy/rollback.sh`. Fast-forward og-public when `infra/deploy` changes. Serialize deploys; rebase the next branch onto the new main.

## 5. Tech debt

- **Codex-style dense TSX**: `src/app/HikeExplore.tsx` and `src/server/planning/hike-plan.ts` pack whole components/flows onto single 500–2000-character lines. Split into components/functions; add unit tests for `HikeDetail` and the list filters.
- **Two Explore implementations**: rider Explore (`ExploreClient`) and hike Explore (`HikeExplore`) share nothing. Converge on one list/card/detail system with an activity adapter.
- **Hike routing bypasses the scoring/role model** (`hike-plan.ts` fakes zero-weight score components and maps every role to one candidate). Give hikes a real candidate model (2–3 options: shortest / most trail / scenic) instead of pretending to be a ride bundle.
- **Inline inspector/hike card layout** is absolute-positioned per breakpoint in several CSS files (`nav.css`, `route-context.css`, `planner-shell.css`, `layers.css`). A floating-chrome layout system (slots: top bar, left column, right column, bottom dock) would end the overlap bugs found today (route bar vs Layers, hike card vs inspector, Edit pill vs Layers header).
- **Static map thumbnails** depend on Mapbox Static Images (quota, ignores our style). MAP-EXPERIENCE-NEXT #18 wants our own server-rendered thumbnails.
- **Catalog files are parsed whole into server memory** (30 MB hikes.json + 104 MB trails.geojson). Move to SQLite/FlatGeobuf/PMTiles with a spatial index before adding NJ + enrichment.
- **Weather sampling count** is decided by the client (`useRouteWeather.ts`); the server still defaults to six. Put the length rule on the server too, and update its tests.
- **`MENU_SETTLE_MS` (700 ms)** in `PlannerMap.tsx` is a timing heuristic for the long-press release. Revisit with real-device telemetry (PostHog) for menu-dismiss-within-1 s rates.
- **Test debt**: `tests/e2e/visual/*.screenshots.spec.ts` live in the critical project and break on intentional UI changes; separate visual snapshots from behaviour gates. Powerplex-only flakes need root-causing (timing waits on "Updating ride…").
- **Python osmium tests** only run on powerplex; docker-dev lacks `osmium`. Add a CI job or skip-marker.
- **Dependabot #4** (eslint 10) has been open for weeks.
- Stale open PRs to triage: #165 (mobile map design handoff), #99 (corridor research), #98 (Muse brief), #97 (native iPhone plan), #46 (CarPlay scaffold).

## 7. Dream state (magic wand)

What "beats Calimoto, Kurviger, REVER, AllTrails and Gaia" looks like:

**Riding**
- Say or type "twisty loop with a good brewery, back by 6" → three honest routes, each with real stops, daylight, weather at every mile, and a 10-second 3D flyover.
- The map is our own Rider style, lit by the real sun, with fun roads glowing and gravel textured, fully offline for PA/NJ/NY including 3D terrain.
- Native turn-by-turn (Ferrostar) with CarPlay, lock-screen Live Activity and Dynamic Island, voice that knows the road ("tight right-hander, 15 mph"), automatic reroute that keeps the ride's character.
- Rider memory: the app learns which roads you love and avoids the ones you skip; "new to me" really means new.
- Live companions: group location (if the owner changes his mind), overdue alerts, crash detection with an emergency card.

**Hiking**
- Every trail in PA/NJ/NY from official + OSM data, deduped, with waterfalls, views, summits, water, parking, real photos with credits, honest time that learns your pace, difficulty from terrain.
- "A 5-mile loop with a waterfall from here" → three loops, mapped, timed, with turn-back time before sunset.
- One tap downloads a hike for no signal: map, terrain, trail graph, wrong-turn buzz, back-to-start breadcrumb, Live Activity on the lock screen.
- Trail-day briefing: weather by hour along the hike, hunting season and blaze-orange note on game lands, closures and fire alerts.

**Platform**
- One floating-chrome layout system, one Explore system for both activities, catalog in a spatial DB, our own map tiles and thumbnails, zero third-party quota risk, real-device telemetry for every critical interaction.
