## How to read the inventory

Tap counts are estimated from the idle phone Map, or from the named prerequisite state, by reading render paths; typing, scrolling, keyboard submission, system permission prompts, and selecting a result are stated separately where relevant. They are not measured iPhone results. A count reaches the control, not necessarily completes its operation. A sheet handle, tab, and button each count as a tap; scrolling does not. Conditional features require their stated state and data. “Hidden” means reachable but hard to discover; “orphaned” means no production entry found, not merely an API without its own button. APIs and application files are implementation capabilities, not evidence that providers are configured.

## Advisor: what actually happens

1. `readQuery` uses local heuristics, so “twisty ride … back by 6” is likely offered as a ride, while ordinary business names and some short requests remain place searches (`src/application/advisor/ride-description.ts:34`, `:78`). The user can miss the feature completely.
2. The model produces a strict partial proposal: destination/loop, named start/finish and one stop, duration or arrive/return-by, departure, curvy/backroads, surface, terrain, novelty, highways, tolls and traffic (`src/application/advisor/advisor-proposal.ts:49`, `:112`, `:190`). It can ask for clarification and answer questions from the existing planned ride. “Twisty ride to a good brewery, back by 6” expresses supported curve and return-by intent, but “good brewery” is not a supported quality-ranked destination search; an unspecified vicinity/stop may require clarification. Model behavior and available service are not verified here.
3. Named places are resolved by `PlaceSearchPort` geocoding, with grounding and vicinity checks (`src/application/advisor/advisor-proposal.ts:600`, `:715`). The prompt specifically leaves vague along-the-way stops unmapped and says halfway coffee must ask for a town (`:203`, `:211`). There is only one `stopPlace` field, no category, rating threshold, candidate list, route corridor or halfway constraint. It does not call `/api/places/along`.
4. Separately, places support optional 0–5 ratings (`src/application/places/types.ts:55`, `src/infrastructure/places/places-geojson.ts:83`) and route corridor queries (`src/server/places/handler.ts:196`); current along-route ordering is route-mile based (`src/application/places/along-route.ts:50`). Some data may have no rating, category coverage, opening hours or provider at all. This is not proof of brewery/coffee/diner coverage, freshness, quality, or source availability. No invented star ratings or “best” claims.
5. The rider sees changes and must accept; stale proposals refresh, then `onApplied` starts planning if required points exist (`src/ui/planner/RideAdvisor.tsx:202`, `:456`, `src/app/PlannerClient.tsx:272`). The server enforces bounded requests, timeout and availability/limit errors (`src/server/advisor/handler.ts:15`, `:99`). No silent mutation or promise of a complete route on unavailable services.

## Dovetail: calm map, clear Ask, contextual tools

**Idle Map:** preserve three tabs, search, category chips, layers and map. Put a persistent, clearly labeled **Ask** button inside or immediately beside the search bar, with an accessible label and no heuristic gate. Search remains a place search. Ask opens a focused sheet with “Describe a ride” and examples such as “Twisty loop to a brewery, back by 6”. One tap reaches the input; typed text plus Send starts the flow. Provide a mode switch Ride / Hike at the same top-level planning surface, per H0; Ride remains default. Ask examples, vocabulary, units and routing profile follow the selected activity. Hike routing, trail data and offline graph are future work, not present capabilities (`docs/vnext/design/HIKE-MODE-PLAN.md:20`).

**Ask result:** show a compact, editable interpretation: start, destination or loop, road/trail character, stops, departure and deadline. Show unknowns and ask a targeted question when needed. Preserve explicit **Plan it** consent and stale-revision protection; then show normal preview with actual time, feasibility, and constraints. If the deadline cannot be met, say so and offer alternatives; never imply a return guarantee. With no advisor or network, keep typed text and offer manual planning. Search results remain independently accessible.

**Quality stops:** make a two-stage proposal: generate a provisional route; query real places near its corridor or destination by requested category; score eligible candidates using disclosed rating and review count only if supplied, detour and route position, open status only if known, and the rider's time budget. Show name, source, rating or “Not rated”, detour and hours/unknown. Let the rider select or replace; reroute and recalculate the deadline before final acceptance. “Good” must not mean an unverified rating. If no suitable data exists, say so and offer unrated choices, another area or manual search; never fabricate. Destination-category searches and along-route stop searches are different intents. Multiple stops require a typed ordered list and bounded iterative planning, not overloading the one-stop schema. Alcohol-related venue searches must not encourage impaired riding.

**Placement contract:** count taps from the active surface to opening a feature/control, excluding text entry, data selection and confirmation; state-dependent controls count from the relevant preview or active ride. Two taps is a design target for reaching each top-level tool, not completing multi-step tasks or a claim about today's UI.

At 393 CSS px, keep controls at least 44 px, use safe-area insets, a sheet that scrolls above the keyboard, visible focus and a predictable close/back path. Show only the search/Ask row and existing map affordances at rest; avoid adding a permanent tool palette. Use existing Day/Night tokens with readable contrast, dynamic type and reduced motion. Verify both themes, keyboard, VoiceOver and sheet detents; do not rely on color alone. Preserve selected route and typed text when switching sheets or recovering from errors. In Hike mode swap terminology, filters and units without suggesting that ride routing, road data or fuel categories describe trails. Offline Ask should state its limits until a local model and offline sources actually exist.
